1. API KEY PROTECTION & SECRETS MANAGEMENT
   THREAT: Exposed API keys in client-side code, repos, or logs
   NSA GUIDANCE: Restrict sensitive credentials to server-side only
   
   CURRENT STATE:
   ✓ API key stored in .env.local (good)
   ✓ Server-side API calls via POST /api/chat (good)
   
   ACTIONS:
   [ ] Add .env.local to .gitignore (prevent accidental commits)
   [ ] Implement environment variable validation at startup
       - Fail fast if ANTHROPIC_API_KEY or ANTHROPIC_MODEL missing
   [ ] Use Vercel's "Protected Environment Variables" for production
   [ ] Rotate API keys quarterly; log access patterns
   [ ] Never log full API keys; log only last 4 chars + timestamp

---

2. END-TO-END ENCRYPTION FOR MESSAGES
   THREAT: Chat messages readable by intermediaries (API servers, proxies)
   NSA GUIDANCE: E2E encryption prevents servers from reading content
   
   CURRENT STATE:
   - Messages sent to Anthropic API in plaintext
   - Suitable for non-sensitive conversations
   - Consider encryption for multi-user or sensitive deployments
   
   ACTIONS (FUTURE PHASE):
   [ ] Evaluate TweetNaCl.js or libsodium.js for client-side encryption
   [ ] Implement optional "secure mode" toggle in UI
   [ ] Store encryption keys in browser localStorage or IndexedDB
   [ ] Document key rotation and recovery procedures
   [ ] Test with QA team before rollout

---

   THREAT: Chat history accessible after user deletes account
   NSA GUIDANCE: Implement secure deletion for data retention compliance

   THREAT: Malicious or vulnerable npm packages compromise app
   NSA GUIDANCE: Audit and monitor all third-party code
   
   CURRENT STATE:

5. NETWORK & TRANSPORT SECURITY
   THREAT: Man-in-the-middle attacks, unencrypted connections
   NSA GUIDANCE: Enforce HTTPS, secure cookies, CORS restrictions
   
   CURRENT STATE:
   - Vercel deployment (HTTPS enforced by default) ✓
   
   ACTIONS:
   [ ] Set Strict-Transport-Security (HSTS) header (1 year min-age)
   [ ] Enable Secure + HttpOnly flags on session cookies
   [ ] Implement CSRF tokens for state-changing operations
   [ ] Restrict CORS to known origins (whitelist Vercel domain)
   [ ] Add Content-Security-Policy header (deny-all by default)
   [ ] Implement rate limiting on /api/chat endpoint (e.g., 10 req/min per IP)
   [ ] Log all API calls with timestamp, user ID (if available), response code

6. AUTHENTICATION & SESSION MANAGEMENT
   THREAT: Session hijacking, unauthorized access to user data
   NSA GUIDANCE: Strong authentication, short-lived tokens, logout procedures
   
   CURRENT STATE:

   - Suitable for anonymous chat; upgrade for multi-user scenarios
   
   ACTIONS (IF MULTI-USER):
   [ ] Implement NextAuth.js or Auth0 integration
   [ ] Use short-lived JWTs (15-30 min expiry)
   [ ] Refresh tokens stored securely (httpOnly cookies)
   [ ] Implement logout that clears all session data
   [ ] Add MFA (TOTP) for sensitive operations

7. LOGGING & AUDIT TRAILS
   THREAT: Inability to detect breaches or track malicious activity
   NSA GUIDANCE: Comprehensive logging without exposing sensitive data
   
   CURRENT STATE:
   - Vercel provides basic request logs
   
   ACTIONS:
   [ ] Log: timestamp, endpoint, HTTP method, response status, user IP

PR AUTOMATION MVP DEPLOYMENT NOTES
   STATUS:
   ✓ Comment-only GitHub PR review MVP is implemented in the app
   ✓ Webhook endpoint exists at /api/github/pr-review
   ✓ Uses Claude + GitHub API to analyze opened/synchronized pull requests
   - Still requires manual Vercel + GitHub configuration to go live

   WHAT THE MVP DOES:
   - Accepts GitHub pull_request webhooks for opened and synchronize
   - Verifies the x-hub-signature-256 header with GITHUB_WEBHOOK_SECRET
   - Fetches PR files, commits, and check status using GITHUB_TOKEN
   - Sends structured PR context to Claude
   - Posts one deduplicated PR comment per PR head SHA
   - Does NOT auto-push code changes yet; comment-only mode for safety

   REQUIRED VERCEL ENV VARS:
   - PR_AUTOMATION_ENABLED=true
   - PR_AUTOMATION_BOT_NAME=Claude PR MVP
   - ANTHROPIC_API_KEY=your_anthropic_api_key_here
   - ANTHROPIC_MODEL=claude-sonnet-4-20250514
   - GITHUB_TOKEN=github_token_with_pull_request_comment_access
   - GITHUB_WEBHOOK_SECRET=replace_with_a_random_secret

   VERCEL CLI COMMANDS:
   1. Link project
      vercel link

   2. Add production + preview env vars
      printf "true" | vercel env add PR_AUTOMATION_ENABLED production
      printf "true" | vercel env add PR_AUTOMATION_ENABLED preview

      printf "Claude PR MVP" | vercel env add PR_AUTOMATION_BOT_NAME production
      printf "Claude PR MVP" | vercel env add PR_AUTOMATION_BOT_NAME preview

      printf "TU_ANTHROPIC_API_KEY" | vercel env add ANTHROPIC_API_KEY production
      printf "TU_ANTHROPIC_API_KEY" | vercel env add ANTHROPIC_API_KEY preview

      printf "claude-sonnet-4-20250514" | vercel env add ANTHROPIC_MODEL production
      printf "claude-sonnet-4-20250514" | vercel env add ANTHROPIC_MODEL preview

      printf "TU_GITHUB_TOKEN" | vercel env add GITHUB_TOKEN production
      printf "TU_GITHUB_TOKEN" | vercel env add GITHUB_TOKEN preview

      printf "TU_WEBHOOK_SECRET" | vercel env add GITHUB_WEBHOOK_SECRET production
      printf "TU_WEBHOOK_SECRET" | vercel env add GITHUB_WEBHOOK_SECRET preview

   3. Redeploy production
      vercel --prod

   GENERATE A WEBHOOK SECRET:
      openssl rand -hex 32

   IMPORTANT:
   - The same generated value must be used both in Vercel as GITHUB_WEBHOOK_SECRET
     and in the GitHub webhook secret field.

   GITHUB WEBHOOK SETUP:
   - Go to: Settings -> Webhooks -> Add webhook
   - Payload URL: https://TU-DOMINIO.vercel.app/api/github/pr-review
   - Content type: application/json
   - Secret: same value as GITHUB_WEBHOOK_SECRET
   - Events: Let me select individual events
   - Select: Pull requests

   GITHUB TOKEN REQUIREMENTS:
   - Prefer a fine-grained token scoped to this repository
   - Permissions needed:
     * Pull requests: Read/Write
     * Contents: Read
     * Metadata: Read

   QUICK VERIFICATION FLOW:
   1. Confirm Vercel env vars are present
   2. Confirm GitHub webhook points to /api/github/pr-review
   3. Open or update a PR
   4. Check webhook delivery result in GitHub
   5. Check Vercel function logs if delivery fails
   6. Confirm the bot posts a PR comment

   FAILURE TRIAGE:
   - 401 from webhook route -> wrong GITHUB_WEBHOOK_SECRET or bad signature
   - 500 from webhook route -> missing env vars or Claude/GitHub API failure
   - No PR comment -> check GITHUB_TOKEN permissions and Vercel logs
   - No webhook delivery -> check GitHub webhook URL and event selection
